# 死亡シミュレーター（仮） — 制作設定資料（2026-11-07）

## 決定事項

**本人が決めたこと**
- 題材は **現実で低い確率で起こる死に方を、ランダムで体験できるゲーム**（ゲーム案ノート 2026-11-07「死亡シミュレーター」）
- 学習メモ「企画・ゲーム設計」と過去のアイデアの学びから、合うものを取り入れる（2026-11-07 依頼）
- 遊び方の核は **ルーレットで死に方を引く**（2026-11-07 選択。一瞬の判断で回避する案・1日を生き延びる案ではなく）
- 見た目は **ゆるいピクトグラム風**。非常口マークのような人型で、死に方は誇張したコミカルな演出。血や残酷な描写はなし（2026-11-07 選択）
- 確率は **実データを調べて出す**。出典をメモに残し、確かな数字がない死に方は採用しない（2026-11-07 選択）

**Claude 案（異論がなければこのまま）**
- スマホ縦画面基準（PC・横持ちもレスポンシブ）、結果画面に控えめな X 共有ボタン
- ルーレットは **「無事」と「死に方」のマスでできた円盤**。1 回まわす＝1 日。無事なら翌日へ、死に方に止まったらそこで終わり。**日がたつほど「無事」のマスが細くなる**（5. ①）
- 回す前に **今日の行き先（家・山・海）を選ぶ**。行き先で円盤に並ぶ死に方が変わる。空から来るもの（落雷など）はどこでも出る（5. ①）
- 死に方は集めると **図鑑（注意標識のカード）** に並ぶ。初めて引いた死に方は大げさに祝う（「おめでとうございます。年間○万人に1人の死に方です」）
- 死亡画面に **実際の数字（年間の死者数・人口比）と「防ぐには」の一行** を出す
- 画面の言葉と見た目を **「注意標識・安全看板」** でそろえる（黄色と黒、ピクトグラム）
- 操作説明・キー設定は入れない（メモリ「操作説明・キー設定は入れない」）

## 1. ゲーム概要

- **タイトル**：死亡シミュレーター（仮）
- **ジャンル・視点**：2D・ルーレット＋コレクション。正面から見た 1 画面
- **コンセプト**：「あなたは今日、何で死ぬ？」現実のまれな死に方を、ルーレットで引いて集める
- **目指す楽しさ**：止まる直前のドキドキ／レアな死に方を引いた時の「マジか」／実際の数字を見て「へえ」／図鑑を埋める
- **基本の体験**：行き先を選ぶ → 円盤が回って止まる → 無事なら翌日、死ねば死因と数字が出て図鑑に載る → もう一度

## 2. ゲーム内容

- **プレイヤーの役割**：ピクトグラムの「ひと」の一生を、1 日ずつ進める
- **基本操作**：タップだけ。行き先のボタンを押す＝その日の円盤が回る。止まる位置は乱数で決まる（プレイヤーの腕では狙えない）
- **基本ルール**
  - 円盤は「無事」のマス 1 つ＋その日の死に方のマス数個
  - 死に方のマスの幅は、実データの死者数の比で決める（多い死に方ほど太く、まれなものほど細い）。差が大きすぎるとまれな物が出ないので、対数で縮めて細すぎないようにする
  - 「無事」の幅は 1 日目が一番太く、毎日細くなる。目安は平均 6〜8 日で死ぬくらい（数値は Claude が調整）
- **ゲームの流れ**：タイトル（注意看板）→ 1 日目の行き先選び → 回る → 無事（ニアミスの一言）→ 2 日目 … → 死亡（ピクトグラムの死亡演出 → 死因カード：数字・防ぐには・初めてなら祝い）→ 結果（生き延びた日数・図鑑の数）→ もう一度／図鑑
- **攻略・工夫の要素**：図鑑の空きを埋めたい死に方がある行き先を選ぶ。ただし行き先ごとに「無事」の幅も少し違う（家は安全寄り、山・海は危険寄りでレアが多い）＝記録を伸ばすか、図鑑を埋めに行くかの判断
- **クリア・失敗条件**：1 回のプレイは必ず死んで終わる。クリアは **図鑑を全部埋めること**。記録は最長の生存日数
- **必要な演出・フィードバック**
  - 減速中に針が死のマスの境目を通るたびにカチッと鳴り、ギリギリで無事に入ると「セーフ」の反応
  - 死亡演出：死に方ごとに 1〜2 秒のピクトグラムのアニメ（例：落雷＝人型がギザギザに光って倒れ、頭上に天使の輪）
  - 初めての死に方：「NEW」の判子・ファンファーレ・レア度（★）
  - 無事の日：ニアミスの一言（近くの死のマスに応じて変わる）

### 死に方の候補（データ調査で確定する）

事故と自然に限る。日本の数字を使う。調査で確かな数字が取れなかったものは外して入れ替える。

| 行き先 | 候補 |
|---|---|
| 家 | 餅をのどに詰まらせる／フグの毒／毒キノコ／屋根からの落雪・雪下ろし |
| 山 | ハチに刺される／マムシにかまれる／落石／雪崩 |
| 海 | 海水浴中の水難（離岸流）／サメ（数字が取れれば） |
| どこでも（空から） | 落雷／竜巻 |
| 隠し枠 | 隕石（日本で死亡の記録なし＝「記録 0 人」として出す案。図鑑の最後の 1 枚） |

**入れないもの**：自殺・自傷、殺人などの事件、テロ・戦争、病気、特定の実在の事故・災害の名前、子どもが犠牲になる場面、いま報道が続いているもの（クマなど）。

## 3. 制作方針

- **使用環境・技術**：ブラウザ（1 枚の HTML）。Canvas 2D・ライブラリなし。`src/` を `sh build.sh` で結合（ほうき立てと同じ構成）
- **素材・制約**：画像素材は使わず、ピクトグラムも標識もコードで描く。効果音は WebAudio で作る。BGM は今回は入れない
- **見た目の方向性**：白地に黒のピクトグラム、注意標識の黄色と黒。赤は死亡の瞬間だけ使う。図鑑のカードはひし形の注意標識に死に方のピクトグラム
- **操作**：タップだけ。PC はクリック
- **優先順位**：円盤が回って止まるドキドキ → 実データの死に方と図鑑 → ピクトグラムの演出

## 4. 技術的な実現方法（Claude）

- 結果は回す前に乱数で決め、円盤はその位置に止まるように減速の曲線を逆算する。最後の数マスは、決まった結果の手前で死のマスをかすめるように見せる
- 死に方のデータは 1 つの表（名前・行き先・年間死者数・人口比・出典・防ぐには・アニメの種類）にまとめ、マスの幅もそこから計算する
- 図鑑と最長記録は localStorage に保存（使えない環境では保存しないで遊べる。verify.html は data: URL で開くので保存されない）
- 共有：スマホは Web Share API で死因カードの画像付き、PC は X の投稿画面（文章＋URL）。文例「【死亡シミュレーター】5日目、落雷で死亡（年間○人）。図鑑 7/12」
- 調べた数字と出典は `docs/データ出典.md` に残す（統計の年・出典 URL・計算方法）

## 5. 仕様上の問題と対応案（実装前の報告）

1. **ルーレットだけだと操作がタップで終わり、判断がない**（設定資料の作り方 2.「判断や攻略につながる」）
   → 行き先選び（記録を伸ばすか図鑑を埋めに行くか）と、細くなる「無事」で判断と緊張を足す。止める位置を指で狙わせる案は「ランダムで体験する」から外れるので入れない
2. **死を笑いにする題材なので、不快さの線引きが要る**
   → 2. の「入れないもの」を守る。演出はピクトグラムで血なし。死因カードに「防ぐには」を必ず付け、豆知識として持ち帰れるものにする（YouTube・X に出すときも説明しやすい）
3. **現実の確率のままだと、まず死なない**（落雷は年間数人＝数千万人に 1 人）
   → 実データは「どの死に方が出やすいか」の比と、カードの数字にだけ使う。何日で死ぬかはゲームとして誇張する。図鑑の下に小さく「死ぬ頻度はゲーム用に大げさにしています」と 1 行だけ添える（操作の説明ではないので入れる）
4. **数字の正確さ**
   → 数字は丸めて「約」と書き、統計の年を併記する。年ごとに変わるものは直近数年の平均。数字が取れない候補は外す
5. **まれな死に方ほど出ないので、図鑑の最後が埋まらない**
   → 対数で縮めて最低の幅を決める。それでも残るときのために、図鑑の空きが少なくなったら未所持の死に方の幅を少し太くする（目安：通しで 15〜20 回遊べば全部そろう）

## 6. 完成条件

共通：起動できる／基本操作が正しく動く／主なルールが機能する／クリア（図鑑コンプリート）まで進める／致命的なバグがない。

この作品の条件：
- 止まる直前のドキドキがある（減速・かすめ・セーフの反応）
- 死に方 12 種前後が実データの数字・出典・防ぐには付きでそろい、出典が `docs/データ出典.md` に残っている
- 行き先選びで出る死に方が変わり、図鑑が保存される
- 死に方ごとのピクトグラムの死亡演出と、初めての死に方の祝い
- 結果画面の X 共有（スマホは画像付き）
- スマホ縦・PC で崩れない。画面の文章が文節の途中で改行しない

## 7. 実装計画

- **Phase 1：円盤の最小版**。行き先なし・仮の死に方 6 種（数字はダミー）。回す → 減速して止まる → 無事なら翌日・「無事」が細くなる → 死亡で死因の文字と生存日数 → もう一度。かすめる演出とカチッという音まで入れる → **テストプレイ通知**（回すドキドキがあるかを本人が確かめる）
- **Phase 2：実データ**。候補を調べて 12 種前後を確定し `docs/データ出典.md` に出典を残す。マスの幅を実データの比から計算。行き先（家・山・海）選び
- **Phase 3：図鑑とご褒美**。注意標識のカードの図鑑・NEW の判子とレア度・ニアミスの一言・保存・図鑑コンプリートの演出
- **Phase 4：演出と仕上げ**。死に方ごとのピクトグラムのアニメ・効果音・タイトル（注意看板）・結果画面と X 共有・スマホ縦/PC の確認 → **テストプレイ通知**（通しで遊べる）
