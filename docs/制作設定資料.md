## 1. ゲーム概要

- **タイトル**：死亡シミュレーター（仮）
- **ジャンル・視点**：2D・ルーレット＋コレクション。正面から見た 1 画面。死亡の瞬間だけ全画面の映像
- **コンセプト**：「あなたは今日、何で死ぬ？」現実のまれな死に方を、ルーレットで引いて集める
- **目指す楽しさ**：止まる直前のドキドキ／ゆるい画面が急に映画のような迫力に変わる落差／レアな死に方を引いた時の「マジか」／実際の数字を見て「へえ」／図鑑を埋める
- **基本の体験**：行き先を選ぶ → 円盤が回って止まる → 無事なら翌日、死に方なら全画面の映像 → 暗転 → 死因カードと数字 → 図鑑に載る → もう一度

## 2. ゲーム内容

- **プレイヤーの役割**：ピクトグラムの「ひと」の一生を、1 日ずつ進める
- **基本操作**：タップだけ。行き先のボタンを押す＝その日の円盤が回る。止まる位置は乱数で決まる（プレイヤーの腕では狙えない）
- **基本ルール**
  - 円盤は「無事」のマス 1 つ＋その日の死に方のマス数個
  - 死に方のマスの幅は、実データの死者数の比で決める。差が大きすぎるとまれな物が出ないので、対数で縮めて細すぎないようにする
  - 「無事」の幅は 1 日目が一番太く、毎日細くなる。**平均 3〜4 日で死ぬ**（Phase 1 のテストプレイで「死ぬまで何回も回すので飽きる」と本人に言われ、6.9 日→3.6 日に短縮。円盤も 4.6 秒→2.8 秒、無事のあとは自動で翌日へ）
- **ゲームの流れ**：タイトル（注意看板）→ 1 日目の行き先選び → 回る → 無事（ニアミスの一言）→ 2 日目 … → 死亡（全画面の映像 → 暗転 → 死因カード：数字・防ぐには・初めてなら祝い）→ 結果（生き延びた日数・図鑑の数）→ もう一度／図鑑
- **攻略・工夫の要素**：図鑑の空きを埋めたい死に方がある行き先を選ぶ。行き先ごとに「無事」の幅も少し違う（家は安全寄り、山・海は危険寄りでレアが多い）＝記録を伸ばすか、図鑑を埋めに行くかの判断
- **クリア・失敗条件**：1 回のプレイは必ず死んで終わる。クリアは **図鑑を全部埋めること**。記録は最長の生存日数
- **必要な演出・フィードバック**
  - 減速中に針が死のマスの境目を通るたびにカチッと鳴り、ギリギリで無事に入ると「セーフ」の反応
  - 初めての死に方：「NEW」の判子・ファンファーレ・レア度（★）
  - 無事の日：ニアミスの一言（近くの死のマスに応じて変わる）

### 死亡演出（全画面の映像）

1 本の流れ（合計 5〜6 秒）：

1. **止まる**：針が死のマスで止まり、円盤の画面が一瞬止まって、色が抜ける（0.3 秒）
2. **映像に切り替わる**：全画面に縦型の映像。いつもの場所にピクトグラムのひとが立っている。のどかな音（0.5 秒）
3. **迫る**：原因がやって来る（空が暗くなり雷雲が光る／山の上から雪崩が来る／ハチの群れが寄ってくる）。ひとが気づいて振り向き、汗のマーク。カメラはゆっくり寄り、揺れが強くなる（3〜4 秒）
4. **直撃で暗転**：当たる瞬間に白（落雷・隕石）か黒（それ以外）に切れて、衝撃音。一拍の無音（0.5 秒）
5. **死因カード**：暗転の上に注意標識のカードが落ちてくる。ここで元のゆるい画面に戻る

- 映像の中のピクトグラムは、円盤の画面と同じ白黒の平らな人型。背景が迫力のある映像でも、ひとだけは標識のまま（それが笑いどころ）
- 血・倒れた体・苦しむ姿は見せない。当たる前で切る
- 暗転の色と音は死に方ごとに決める

### 死に方の候補（データ調査で確定する）

事故と自然に限る。日本の数字を使う。調査で確かな数字が取れなかったものは外して入れ替える。

| 行き先 | 候補 | 映像の案（人なし・カメラ固定） |

| 家 | フグの毒 | 夜の台所、まな板の上のフグ。照明がちらつく |

## 3. 制作方針

- **使用環境・技術**：ブラウザ。Canvas 2D・ライブラリなし。`src/` を `sh build.sh` で結合（Phase 1 で作った構成）。映像は別ファイル（`media/*.mp4`）
- **素材・制約**
  - 死亡演出の背景も **全部コードで描く**（2026-11-07 に AI 動画から変更。`src/45-scenes.js`。動画・画像素材は使わない）。クレジットも追加購入も使わない
  - ピクトグラムも標識もコードで描く
  - 効果音は WebAudio で作る。動画の音は使わない（音量と暗転のタイミングをそろえるため）。BGM は今回は入れない
- **見た目の方向性**：円盤・図鑑・カードは白地に黒のピクトグラム、注意標識の黄色と黒。赤は死亡の瞬間だけ。映像は暗め・コントラスト強め・映画の予告編のような色で、ゆるい画面との落差をはっきりさせる
- **操作**：タップだけ。PC はクリック
- **優先順位**：円盤が回って止まるドキドキ（Phase 1 済み）→ 映像の試作 1 本で落差が面白いかを確かめる → 実データの死に方と図鑑 → 残りの映像と仕上げ

## 4. 技術的な実現方法（Claude）

- 結果は回す前に乱数で決め、円盤はその位置に止まるように減速の曲線を逆算する（Phase 1 済み）
- 死に方のデータは 1 つの表（名前・行き先・年間死者数・人口比・出典・防ぐには・動画ファイル・ピクトグラムの足もとの位置と大きさ・暗転の時刻と色）にまとめる
- **場面の描画**（2026-11-07 変更）：全画面の Canvas に、死に方ごとの背景（`Scenes.<id>(ctx, t, p)`）を毎フレーム描き、その上にピクトグラムを描く。寄り・揺れは Canvas をまとめて拡大・移動する。動画ファイルがないので読み込みも要らず、スマホの自動再生の制限も受けない。音は WebAudio
- **場面がない死に方**は、Phase 1 の簡易演出（寝た人）にして遊びを止めない
- 足もとの位置・大きさは死に方ごとの表（`DEATHS[].cine`）で合わせる
- 図鑑と最長記録は localStorage に保存（使えない環境では保存しないで遊べる。verify.html は data: URL で開くので保存されない）
- 共有：スマホは Web Share API で死因カードの画像付き、PC は X の投稿画面（文章＋URL）。文例「【死亡シミュレーター】5日目、落雷で死亡（年間○人）。図鑑 7/12」
- 調べた数字と出典は `docs/データ出典.md`、動画の生成プロンプトと設定は `docs/映像の作り方.md` に残す

## 5. 仕様上の問題と対応案（実装前の報告）

> 2026-11-07 の変更（背景をコードで描く）で、2〜3・5〜7 の「AI 動画」前提の問題（生成を断られる・カメラが動く・ページが重い・クレジット・規約）は**なくなった**。代わりの問題は「**コードで描いた絵が AI 動画より迫力で劣る**」で、落雷で試した結果（Phase 2）を本人が確かめる。2 の「人を映さない」「当たる前で切る」は引き続き守る。

1. **ルーレットだけだと操作がタップで終わり、判断がない**（設定資料の作り方 2.「判断や攻略につながる」）
   → 行き先選び（記録を伸ばすか図鑑を埋めに行くか）と、細くなる「無事」で判断と緊張を足す。止める位置を指で狙わせる案は「ランダムで体験する」から外れるので入れない
2. **AI 動画で「人が死ぬ場面」を作ると、生成を断られやすく、生々しくもなる**
   → 動画には人を映さず、風景と原因だけにする。ひとはピクトグラムで重ねるので、どの映像でも同じ見た目になる。当たる前で暗転するので、血や倒れた体は出ない
3. **AI 動画はカメラが勝手に動き、重ねたピクトグラムが背景から浮く**
   → 生成するときにカメラ固定を指定し、動いてしまったものは作り直すか、ピクトグラムを置く位置を動きの少ない所にする。寄り・揺れはゲーム側で付ける
4. **映像だけで遊びのテンポが落ちる**（1 回 5〜6 秒、何度も死ぬゲーム）
   → 初めての死に方は最後まで見せ、2 回目からはタップで暗転まで飛ばせる。映像を 6 秒以内に収める
5. **ページが重くなる**（動画 13 本で 13MB 前後）
   → 最初に全部は読まず、死亡に決まった時点でその 1 本だけ読む。読み込めないときは簡易演出で続ける
6. **クレジットの消費と作り直し**
   → まず落雷 1 本だけ作って、落差が面白いか・重ね合わせが成り立つかを本人に見てもらってから残りを作る。生成の前に、1 本あたりの消費と残高を伝える
7. **動画の使い方の条件**
   → Higgsfield のプランで、生成した動画をゲームに入れて公開・動画投稿してよいかを、最初の生成の前に確かめる
8. **現実の確率のままだと、まず死なない**（落雷は年間数人＝数千万人に 1 人）
   → 実データは「どの死に方が出やすいか」の比と、カードの数字にだけ使う。何日で死ぬかはゲームとして誇張する。図鑑の下に小さく「死ぬ頻度はゲーム用に大げさにしています」と 1 行だけ添える（操作の説明ではないので入れる）
9. **数字の正確さ**
   → 数字は丸めて「約」と書き、統計の年を併記する。年ごとに変わるものは直近数年の平均。数字が取れない候補は外す
10. **まれな死に方ほど出ないので、図鑑の最後が埋まらない**
   → 対数で縮めて最低の幅を決める。図鑑の空きが少なくなったら未所持の死に方の幅を少し太くする（目安：通しで 15〜20 回遊べば全部そろう）

## 6. 完成条件

共通：起動できる／基本操作が正しく動く／主なルールが機能する／クリア（図鑑コンプリート）まで進める／致命的なバグがない。

この作品の条件：
- 止まる直前のドキドキがある（減速・かすめ・セーフの反応）
- **死に方ごとに全画面の映像があり、ゆるい画面からの落差が出ている**（コードで描いた背景にピクトグラムがなじんで立ち、迫って、直撃で暗転する）。2 回目からは飛ばせる。読み込めないときも簡易演出で遊べる
- 死に方 12 種前後が実データの数字・出典・防ぐには付きでそろい、出典が `docs/データ出典.md` に残っている
- 行き先選びで出る死に方が変わり、図鑑が保存される
- 初めての死に方の祝い
- 結果画面の X 共有（スマホは画像付き）
- スマホ縦・PC で崩れない。画面の文章が文節の途中で改行しない
